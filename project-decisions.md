# Project Decisions

Durable implementation and architecture decisions for UniFrag. This file is the source of truth for decisions; keep entries concise, dated, and actionable.

## Decision 2026-09-17: Cleave 1,4-Dioxin COF Linkages and Tag Multi-Bond Linkages Explicitly
- Context: Dioxin-linked COFs (e.g. `1097.cif`, HHTP + perfluoroarene chemistry) were not decomposable by any existing cleavage rule, so Path J failed and the generic `{"B","O"}` fallback produced a single-oxygen "node" and a truncated 53-atom fragment with no minimized version. 50 of the 884 HCNO structures carry the motif.
- Decision:
  1. Cleave the 1,4-dioxin linkage: in the six-membered ring `O1-C2-C3-O4-C5-C6`, the carbon pairs `{C2,C3}` and `{C5,C6}` belong to two different aryl systems (found as connected components after deleting every O). Sever the two C-O bonds on one side, keeping the oxygens with the **larger** aryl system — the polyol-derived building block.
  2. Tag severed bonds that belong to one chemical linkage at detection time (`linkage_of`, keyed by `frozenset({u,v})`), and have `_count_linkages` merge bonds that share an endpoint **or** carry the same tag.
- Consequences: `1097` decomposes into a triphenylene node (`H6 C18 O6`, 3-connected) and a benzene linker (`H2 C6`, 2-connected); its normal fragment grows 53 -> 120 atoms (node + all 3 linkers per layer) and it gains an 88-atom minimized fragment via the node+one-linker fallback. Minimized coverage across the 20-structure HCNO batch reached 20/20. `1031` and `211` decompositions are unchanged and the dioxin rule cuts nothing on them.
- Why tagging was mandatory: a dioxin severs `C2-O1` and `C3-O4`, which share no endpoint, so endpoint-based grouping alone counted the benzene linker's four severed bonds as four connections and classified it as a node — leaving zero linkers and aborting Path J. Merging by *adjacency* of attachment atoms was rejected as ambiguous, since adjacent attachment atoms indicate one linkage for a dioxin but two independent linkages for an ortho-disubstituted aryl; recording linkage membership where the rule fires is exact.
- Known limitation: the "oxygens go to the larger aryl system" tie-break is heuristic. It matches HHTP-type chemistry but would assign oxygens to the wrong block if the polyol unit were the smaller one. This only changes which helper-library file owns the O; the assembled fragment is unaffected because junctions reconnect geometrically.

## Decision 2026-09-17: Minimized-Fragment Reduction Threshold (20 atoms) and a Node-Plus-One-Linker Fallback for Large-Node COFs
- Context: A minimized fragment that is nearly the same size as its normal counterpart is a near-duplicate and wastes QM budget. Separately, the standard minimize strategy (keep one full linker, trim the remaining linkers to their first ring) cannot shrink COFs whose node dominates the fragment and whose linkers are already small — e.g. `1031.cif` (node 39 atoms, linker 12) reduced by 0 atoms. In a 20-structure HCNO batch, 8 structures produced no usable minimized fragment at all.
- Decision:
  1. **COF only:** a minimized COF fragment is kept only when it is at least `MIN_ATOM_REDUCTION_FOR_MINIMIZE_COF = 20` atoms smaller than its normal counterpart. **This threshold is deliberately NOT applied to MOFs** — `_process_mof_file` keeps its original unconditional behaviour, so MOF output is unaffected.
  2. For COFs, when the standard strategy falls short of that threshold, retry once with `single_linker=True`: keep the node plus exactly ONE complete linker and drop the remaining linkers entirely, letting the existing post-merge capping close the node's open attachment points. The better of the two candidates is used, and if neither clears the threshold the minimized fragment is skipped.
- Why MOFs are excluded: measured across the IRMOF series (19 structures), reductions are 21, 21, 21, 21, 21, 21, 21, 21, 21, 21, 21, 21, 25, 71, 71, 71, 111, 121, 121, 137 — bimodal, with **12 of 19 clearing a 20-atom bar by exactly one atom** and nothing between 25 and 71. Any threshold in that region sits on a cliff edge and would silently delete valid MOF minimized fragments, so the rule is scoped to COFs and the constant is named `_COF` to keep it from drifting back.
- Consequences: In the 20-structure HCNO batch, minimized-fragment coverage rose from 12/20 to 19/20 — 8 structures gained a minimized fragment they previously lacked (`1031` 168->120, `211` 192->128, `167` 174->126, `1156` 145->103, `1023` 126->90, `142` 124->82, `557` 124->72, `137` 114->66) and `1110` improved from a marginal 93 to 67. All remain valence-complete and even-electron. `1097.cif` lost its minimized fragment (its reduction was exactly 15, under the new threshold, and it has no node/linker decomposition so the fallback cannot apply) — accepted as the intended effect of the stricter threshold.
- Alternatives considered: choosing the strategy up front from a chemical criterion such as `node_atoms > linker_atoms`; rejected on measured data — across the batch that rule mis-handles 4 of 20 cases (it would needlessly switch `856` and `1110`, where trimming already works, and it misses `137`/`557`, where node and linker are the same size yet trimming still achieves nothing). Deciding by measured outcome reuses the threshold already in place instead of adding a second tunable heuristic, and adapts to any topology. The fallback deliberately keeps the node intact rather than also trimming it, since dropping arms off a node such as `1031`'s triazine would change the electronic environment the cluster model is meant to represent.

## Decision 2026-09-16: Cleave Benzoxazole Linkages, and Classify COF Node vs Linker by Linkage Count Rather Than Attachment-Atom Count
- Context: `coffragmentor.py` recognised only two COF linkage chemistries (B-O, imine C=N). Benzoxazole-linked COFs (e.g. `1031.cif`, a benzoxazole-linked triazine COF) were therefore never decomposed — the oxazole C-N bond is inside a five-membered ring and is deliberately skipped by the imine rule's `in_small_ring` guard — so Path J returned no node/linker and extraction fell through to the generic fallback, whose `bo_node_species = {"B","O"}` heuristic then treated each isolated ether oxygen as its own node, yielding a single-atom "node" and a one-armed fragment. A motif scan found ~127 of the 884 HCNO CoRE-COF structures carry this motif.
- Decision:
  1. Cleave the benzoxazole/oxazole linkage in `COF.fragment()`: the oxazole C2 carbon is identified as a carbon with exactly one O and one N neighbour such that deleting it leaves a 3-edge O-x-y-N path (closing a five-membered ring through it). Both its C-O and C-N bonds are severed, separating the aldehyde-derived building block from the aminophenol-derived one.
  2. Classify components as node vs linker by the number of distinct **linkages** (`_count_linkages`) rather than the number of attachment atoms. Severed bonds that share an attachment atom or share an external partner atom belong to one chemical linkage and are counted once.
- Consequences: `1031.cif` now decomposes correctly into a triazine node (`H12 C24 N3`: triazine + 3 phenyl + 3 aldehyde C) and a benzoxazole linker (`H2 C6 N2 O2`), and its normal fragment grows from a malformed 71 atoms to a correct 168 atoms (1 node + all 3 linkers, bilayer). Change 2 was mandatory, not cosmetic: a benzoxazole linker exposes 4 attachment atoms (2 O + 2 N) and was otherwise misclassified as a node, leaving zero linkers and aborting Path J. For single-bond linkages (imine, boroxine) linkage-counting is identical to attachment-atom counting, so existing COFs are unaffected — verified byte-identical output for 19 of 20 structures in the HCNO test batch and 8/8 on both fast-test suites.
- Alternatives considered: counting distinct external partner atoms instead of linkage groups; rejected because it over-counts on the aldehyde side of a two-bond linkage (a C2 carbon has two partners, O and N), which would misclassify a dialdehyde-derived 2-connected linker as a node in COFs with the reversed node/linker topology. Also considered fixing only the `{"B","O"}` fallback heuristic; rejected as insufficient — it would stop the degenerate single-O node but still leave the structure with no valid node/linker decomposition, since the real fix belongs in the linkage chemistry.

## Decision 2026-09-16: COF-Only Valence-Deficit Capping for Severed Double-Bond Cut Sites, Kept Strictly Isolated from MOF Code
- Context: COF imine cleavage (`coffragmentor.py` cuts C=N bonds where the carbon has heavy degree 2) leaves the node's nitrogen and the linker's carbon with only 1 heavy neighbor. The existing shared `_cap_open_oxygens` (used by both MOF and COF) has no branch for a 1-heavy-neighbor carbon and only partially/incorrectly caps the analogous nitrogen case, leaving these cut sites uncapped or under-capped in COF Path J outputs (`FragCof`, `FragCofMin`, and the `OnlyLinker` QM export). The user explicitly required zero behavior change to MOF code while fixing this.
- Decision: Implemented the fix entirely inside `COFFragmenter` (new methods `_cap_severed_double_bond_sites` and `_make_cof_qm_ready`), never touching `BaseFragmenter`, `MOFFragmenter`, or the shared `_cap_open_oxygens`/`_make_qm_ready_linker` functions themselves. `_cap_severed_double_bond_sites` flags any C/N atom with exactly 1 bonded heavy neighbor (regardless of existing H) and adds `target_valence[sp] - (heavy_count + existing_H_count)` new hydrogens — a true per-atom valence deficit, since a native H may or may not already be present depending on whether the cut carbon/nitrogen kept its own substituent H. It is applied to the isolated node molecule and each isolated linker image *before* merging (post-merge application is unreliable: a spatially nearby atom from a different merged image can mask the true local degree). Also added symmetric `self.extracted_nodes` tracking and a new `OnlyNode` QM-ready ExtXYZ export (`<stem>FragCofOnlyNode`), mirroring the existing `OnlyLinker` export, so both COF building-block types are QM-ready.
- Consequences: Validated on `211.cif` (imine-linked HCNO COF from the CoRE-COF DT1242-v7.0 database): all 4 exported fragment types (`FragCof`, `FragCofMin`, `OnlyLinker`, `OnlyNode`) went from having systematically under-coordinated or fully bare cut-site heavy atoms to zero valence deficits, all even-electron. `./run_fast_test.sh` (MOF) and `./run_fast_test.sh --kind cof` both remain 8/8 passing, confirming no regression in either family.
- Alternatives considered: A blanket "target valence minus geometric degree" rule applied to ALL carbons; rejected because normal aromatic/carbonyl carbons are legitimately 3-coordinate (via an intact double bond that plain distance-based bonding can't detect), so a blind valence-4 rule would incorrectly add a spurious 4th substituent to every ordinary ring carbon. Restricting the trigger to "exactly 1 heavy neighbor" is a narrow, verified-safe signature specific to a severed double-bond cut site. Thread­ing exact cut-bond metadata from `coffragmentor.py`'s graph edge-removal step through to the capping logic was also considered as a more rigorous alternative; deferred as a possible follow-up if the geometric heuristic is ever found to misfire (e.g. on nitrile-containing COFs, which are not cut by the current cleavage rules and so have not been observed to trigger this rule).
- Correction (same day): capping the node and each linker image in isolation *before* they are merged in `_try_coffragmentor_node_linker_fragment` was itself wrong and was reverted. A node/linker cut atom that the merge actually reconnects (its true bonding partner, e.g. the attached linker's cut carbon, is restored to within a real bond distance once both pieces sit at their correct relative crystallographic positions) must be left alone; independently pre-capping both sides created two spurious dead-end groups (`-NH2` + a `-CH3`-like stub) at what should be one real bond — and this passed the valence-deficit check on each isolated side, so it wasn't caught until visual inspection of the assembled fragment. The rule is now applied only *after* merging: a genuinely still-dangling atom (no reconnection occurred within this fragment, e.g. a linker's far end going to a second, non-included node copy) is still distinguishable there by having exactly 1 heavy neighbor, while a properly-reconnected junction now has 2.
- Correction (same day): the newly capped hydrogens were also placed with wrong angles — `place_capping_h`'s cone search only avoids steric clashes, so placing 2 new H on the same atom (e.g. converting a bare imine N into `-NH2`) left the first H nearly collinear (180 degrees) with the anchor bond instead of a proper pyramidal angle. Fixed by having `_cap_severed_double_bond_sites` track its own newly-added H indices per atom and immediately call the existing (previously unused-in-practice) `BaseFragmenter.refine_h_geometry_with_rdkit` — a local UFF relaxation with every other atom fixed — restricted to just those indices. Verified angles post-fix: `-NH2`/`-CH3`-like capped sites measure ~106-120 degrees, consistent with normal substituent geometry.

## Decision 2026-07-17: Exporting QM-Ready "OnlyLinker" Fragments to ExtXYZ Collections
- Context: While raw linkers are exported as reference templates to the helper libraries (`mof_linkers_lib/` and `cof_linkers_lib/`), they lack capping at boundary cut sites. The user requested generating a fully capped, QM-ready version of each unique linker and saving it as an extra fragment in the main `fragments_collection.extxyz` file, labeled `"<COF/MOF_Name>FragCofOnlyLinker"` or `"<COF/MOF_Name>FragMofOnlyLinker"`. Furthermore, helper libraries should remain strictly uncapped (stripping any crystallographic N-H/O-H boundary hydrogens to keep the core template raw).
- Decision: Implemented a robust extraction and processing pipeline:
  1. Captured raw unique linkers during MOF/COF component exports into an instance list `self.extracted_linkers`.
  2. Moved `_clean_linker_molecule` to `BaseFragmenter` and added class attribute `METALS = set()`. Set `self.structure = struct` early in both extraction pathways to expose the periodic structure context.
  3. Inside `_clean_linker_molecule`, identified boundary atoms by comparing their original periodic heavy degree to their extracted linker heavy degree. Any Hydrogen atoms directly bonded to these boundary atoms (like the crystallographic enamine N-H hydrogens in `COF-TpAzo`) are stripped when exporting to helper libraries (`mof_linkers_lib/` / `cof_linkers_lib/`).
  4. Prepared QM-ready linkers using `_make_qm_ready_linker`, which applies boundary H-capping (`_cap_open_oxygens`), force-field capping H geometry optimization, and odd-electron multiplicity correction (`fix_odd_electron_multiplicity`). Flushed these to the main collection.
- Consequences:
  1. Main collections now contain both coordination environment clusters (`*FragCof`, `*FragCofMin`) and the isolated, QM-ready capped linkers (`*FragCofOnlyLinker`).
  2. For `COF-TpAzo`, the raw helper template in `cof_linkers_lib/COF-TpAzo_00.xyz` is now correctly stripped to `H8 C12 N4` (uncapped), while the QM-ready fragment in the ExtXYZ collection is capped to `H10 C12 N4` (QM-ready).
- Alternatives considered: Capping the helper template files directly; rejected because helper libraries are intentionally kept as raw periodic templates, whereas `fragments_collection.extxyz` is the designated repository for all QM-ready fragments.

## Decision 2026-07-17: Protecting Terminal Functional Group Atoms in COF Linkers by Cleaving Imine C=N Bonds Directly
- Context: In `COF-TpAzo` (and other imine/hydrazone/azine COFs), cutting the aromatic C-N single bonds stripped the terminal Nitrogen atoms from the amine-derived linkers, leaving the linkers with terminal Carbon atoms (non-physical for diamine building blocks like azodianiline).
- Decision: Refined the C-N cleavage heuristic in `COF.fragment()` inside `coffragmentor.py` to target C-N bonds where the Carbon has a heavy-atom degree of exactly 2 (which represents the imine `C=N` double bond itself), rather than cutting the aromatic C-N single bonds where Carbon has a heavy-atom degree >= 3.
- Consequences:
  1. Linkers derived from amine building blocks (like `4,4'-azodianiline`) retain their terminal Nitrogen atoms, resulting in complete, correct formulas such as `H10 C12 N4` (complete diamine).
  2. Nodes derived from aldehyde building blocks (like `1,3,5-triformylphloroglucinol`) retain their formyl Carbon atoms, resulting in complete, correct formulas such as `H3 C9 O3` (aldehyde/ketone).
  3. This ensures that the terminal functional group atoms (N or O) are correctly partitioned and stay with their corresponding original chemical building blocks.
- Alternatives considered: Keeping the aromatic single bond cut and manually reconstructing the terminal functional atoms; rejected because cutting the imine double bond directly is topologically clean, chemically correct, and avoids any reconstruction overhead.

## Decision 2026-07-09: Restricting Minimized MOF Fragments to Exactly One Full Linker
- Context: Minimized fragments (`*Min`) should represent minimal cluster models of the coordination environment for low-cost QM calculations. Previously, the SBU minimization kept all coordinating linkers full if their bridge metals were separated by > 4.5 Å, which kept multiple linkers full and generated excessively large minimized fragments (e.g. still containing 5 or 6 complete linkers).
- Decision: Restructured `MOFFragmenter._get_fragment` to sort the coordinating components (linkers) by size and set `keep_linker = True` for **exactly one** largest linker, while setting `keep_linker = False` for all other linkers.
- Consequences: Minimized fragments now contain exactly one full linker, and all other coordinating linkers are minimized (truncated to their first coordination sphere / phenyl ring, and capped with hydrogens). This guarantees minimal, chemically complete coordination environment clusters (e.g., `Mg2_dobpdc` minimized fragment size is successfully capped at 104 atoms while the normal fragment size is 183 atoms).
- Alternatives considered: Keeping all linkers minimized (truncated); rejected because keeping at least one full linker is critical to study the full organic linker environment and boundaries.

## Decision 2026-07-09: Excluding Metal-Carbon and Metal-Hydrogen Bonds in MOF Node and Linker Extraction
- Context: In fallback MOF SBU node extraction, carboxylate carbons and capping hydrogens were being incorrectly included as part of the metal SBU nodes (e.g. `Mg1 C3 O5` instead of `Mg1 O5`). This happened because `is_valid_bond` returned `True` for any bond involving a metal under 2.6 Å, which mistakenly matched metal-to-carboxylate-carbon distances (typically 2.50-2.55 Å).
- Decision: Refined `MOFFragmenter.is_valid_bond` to explicitly return `False` if either atom is a metal (`self.METALS`) and the other is Carbon (`C`) or Hydrogen (`H`).
- Consequences:
  1. Extracted SBU nodes are now chemically clean inorganic nodes without any carbon/hydrogen inclusions (e.g., the fallback node for `Mg2_dobpdc_CoRE_ASR` is successfully cleaned from `Mg1 C3 O5` to `Mg1 O5`).
  2. The SOAP local environment similarities for the Mg dataset at a 6.0 Å cutoff increased significantly from **84.94% to 87.48%** (and from 98.55% to 99.25% at 3.0 Å) due to cleaner node environment representations matching parent crystals perfectly.
- Alternatives considered: Decreasing the metal coordination cutoff radius below 2.5 Å; rejected because some legitimate metal-oxygen coordinate bonds (e.g. in hydrated metal clusters) exceed 2.5 Å, and filtering by element type (C/H) is much safer and chemically correct.

## Decision 2026-07-09: Swapping CrystalNN with JmolNN for Guest Removal and Refining Fallback Linker Extraction
- Context: In guest cleaning and pre-processing, `CrystalNN` was causing severe framework truncation by failing to identify organic-organic covalent bonds (e.g. C-C, C-N, C-O) in molecular linkers, leading to framework fragmentation and silent deletion of linker cores. Furthermore, fallback linker extraction was outputting truncated linkers due to metal seeds stealing atoms and coordination shell atoms being skipped.
- Decision:
  1. Prioritize `JmolNN` (covalent radii-based coordination model) over `CrystalNN` as the default framework component solver in `preprocess_dataset.py` and `remove_guests.py`. Trigger the `CrystalNN` fallback block only on runtime exceptions, rather than when zero guest atoms are isolated.
  2. Refine `_fallback_export_mof_node_linker` in `fragmentation_oop.py` to exclude metals from being selected as organic linker seeds.
  3. Initialize `global_vis` as an empty set (instead of `expanded_node`) and remove `v in expanded_node` from the BFS skip condition to allow the coordinates of coordinating carboxylate and N-oxide oxygens to be completely collected.
- Consequences: Truncated organic linkers are fully resolved to their complete chemical compositions (e.g., dipyridine N,N'-dioxide is restored from 6 atoms to the complete 22-atom `C10 H8 N2 O2` molecule; terephthalate is restored to 16-atom `C8 H4 O4`; and dobpdc is restored to 26-atom `C14 H6 O6`).
- Alternatives considered: Manually capping and reconstructing missing atoms with geometry optimization; rejected because restoring correct extraction connectivity from the intact crystal is much more robust and preserves original bond lengths/angles.

## Decision 2026-06-24: Continuous Local SOAP Fingerprint Representation with Multi-Cutoff Support, Pre-Loading Caching, and RMSD Analysis
- Context: Analyzing fragment representation using discrete coordination number categories (e.g. `CN=4 [O4]`) fails to capture continuous structural distortions, exact local symmetry, or variations in coordination shells (such as the presence of capping hydrogens vs parent coordinates). Furthermore, analyzing multiple cutoffs sequentially is slow if crystal files are parsed repeatedly from disk.
- Decision: Implemented a local SOAP (Smooth Overlap of Atomic Positions) fingerprint analysis script `runUniFrag/analyze_zn_soap.py` using `dscribe` supporting a list of user-configurable cutoffs (`--r_cut`, default `[6.0]`).
  1. **Caching Optimization**: Pre-loads and parses CIF structures once at startup, caching them in memory as ASE Atoms objects to achieve a `~30x` speedup during multi-cutoff loops.
  2. **Fingerprint RMSD**: In addition to Cosine Similarity, computes the Root-Mean-Square Deviation (RMSD) between raw SOAP fingerprint vectors of parent Zn centers and their best-matching fragments.
  3. **Multi-Cutoff Output**: Generates reports (`zn_cr_cifs_noduplicated/zn_soap_analysis_{r_cut:.1f}.md`) and side-by-side PCA/UMAP plots (`zn_cr_cifs_noduplicated/zn_soap_distribution_{r_cut:.1f}.png`) dynamically suffixed by cutoff.
- Consequences: Continuous structural coverage and fingerprint deviations are formally calculated, showing expected chemical trends (tighter cutoffs have lower RMSD and higher similarity; e.g., 3.0 Å has median similarity of 0.9999 and median RMSD of 0.0018, whereas 6.0 Å has median similarity of 0.9957 and median RMSD of 0.0452). Caching ensures four cutoffs execute in under 2 minutes.

## Decision 2026-06-24: Configurable Processing Timeout and Relocation of Timed-Out Structures
- Context: Processing certain highly-connected, large, or topologically complex crystal structures using `fragmentation_oop.py` could hang indefinitely or consume excessive CPU time.
- Decision: Introduced a configurable timeout parameter `--timeout` (default 300.0s / 5 minutes) using a Unix `SIGALRM` based context manager. If a structure execution exceeds this timeout, the worker process catches a custom `TimeoutError` (inheriting from `BaseException` to prevent swallowing by local `except Exception` blocks), moves the timed-out CIF or PDB file to a `timed_out_structures/` folder within its parent directory, logs the timeout event to the console, and updates the summary CSV with `"TIMEOUT"` values to gracefully proceed with the batch.
- Consequences: Long-running or stuck structures are isolated automatically, preventing stalls in the batch execution pipeline.

## Decision 2026-05-28: Heavy-Atom Formula-Only Chemical Identity Key for Robust Conformer Deduplication
- Context: The user noticed that chemically equivalent structures (same formula and connectivity, but with minor conformational/torsional variations or hydrogen-capping differences) were not flagged as duplicates under the collection-level deduplication. Originally, deduplication relied on the strict `_species_coords_unique_key` (which encoded exact coordinates and pairwise distances), meaning conformers were treated as unique.
- Decision: Implemented a robust chemical identity key helper (`_chemical_identity_key`) for collection-level duplicate detection. Instead of using exact coordinates or pairwise distance histograms (which suffer from binning issues due to small lattice parameter shifts across CIF files), the new key filters the fragment down to heavy atoms (excluding Hydrogen atoms entirely) and constructs a sorted count tuple of only heavy element occurrences (e.g. `(("C", 12), ("O", 4), ("Mg", 2))`).
- Consequences: All collection-level duplicate checks across MOF, COF, and Bio modes (including sliding windows and batch directory sweeps) correctly identify and group chemically equivalent structures/conformers as duplicates. This ensures that only unique chemical topologies are saved to the `.extxyz` collections, while duplicates are correctly documented in the summary `.csv` files as duplicates.

## Decision 2026-05-26: Bypass `moffragmentor` for 1D Infinite SBUs
- Context: The node+linker approach using `moffragmentor` overrides the `--nmetals` fallback for 1D rods because it merges unit-cell nodes blindly without understanding infinite slicing.
- Decision: Check `getattr(result, "has_1d_sbu", False)`. If True, intentionally skip the `moffragmentor` extraction and fall back to Path B (Infinite), which correctly builds the supercell and slices the 1D chain to exactly `--nmetals`.
- Consequences: Rod MOFs respect the `--nmetals` requested by the user, providing an exact cut of the infinite metal chain.

## Decision 2026-05-26: ExtXYZ label formatting uses CamelCase
- Context: The user requested labels without underscores for the generated `.extxyz` files.
- Decision: Updated label formats across MOF, COF, and Bio modes to use CamelCase without underscores (e.g., `2015Mgins3ASR1FragMof`, `2015Mgins3ASR1FragCof`, `2015Mgins3ASR1W001`).
- Consequences: All ExtXYZ files output CamelCase labels in their `label=` property.

## Decision 2026-05-25: Smart H-capping for non-metal bonded Oxygen atoms
- Context: Oxygen atoms that are part of functional groups (like Carboxylate, Sulfonyl, etc.) and coordinate to metals were incorrectly being capped with too many hydrogens (e.g., 2 H's like water) when bonds to the metal were cut.
- Decision: Implemented functional-group-aware priority for H-capping. The BFS cap assignment checks the heavy non-metal neighbors (C, S, P) of an Oxygen. If an Oxygen is bonded to a C/S/P, it is strictly capped with a maximum of 1 H (representing an -OH group). If it is a pure metal-coordinated water (no non-metal heavy neighbors), it is capped with up to 2 H's.
- Consequences: Prevents over-protonation of carboxylate and sulfonyl oxygens, yielding chemically accurate terminal groups.

## Decision 2026-05-25: Merging fragmented moffragmentor nodes for polynuclear SBUs
- Context: `moffragmentor` was erroneously splitting discrete polynuclear SBUs (like Mg dinuclear clusters) into isolated 0D nodes, causing the node+linker path to fail to build the full SBU.
- Decision: Added an iterative node-merging step inside `_try_moffragmentor_node_linker_fragment`. If metal atoms from different moffragmentor nodes are within 3.5 Å (accounting for periodic images), the nodes are merged into a single polynuclear SBU before continuing.
- Consequences: Dinuclear and clustered SBUs are correctly kept intact when building the node+linker fragment via the primary Path J.


### Decision 2026-05-24: [REVERTED] Automated QM-readiness validation, hydrogen saturation, neutralization engine, and ring planarity gating
- Context: For seamless Quantum Chemistry (QM) calculations on the generated fragments, it was proposed to make all outputs formally neutral (charge = 0) and closed-shell singlet (spin multiplicity = 1).
- Decision: Reverted fully on 2026-05-25. The saturation engine and readiness validation loops added severe performance overhead, especially on large, complex metal-organic frameworks (MOFs). The codebase was rolled back to commit `84b53581dbf3dcf52b2426ce98d17a8bdc7fc2ae` to restore the original, highly optimized geometric and chemical capping rules without RDKit iterative bond perception.
- Consequences: All H-saturation/neutralization heuristics and iterative checks are removed. Fragmentation times returned to their fast baseline levels.


## Decision 2026-05-22: Unified Single-File/Folder Execution with Atomic Collection Updates and No Individual XYZ Files
- Context: Previously, running fragmentation on a single file produced separate `.xyz` files and wiped the target collections, whereas directory execution appended frames/rows. The user requested completely eliminating individual `.xyz` files (relying only on `fragments_collection.extxyz` or `bio_fragments_collection.extxyz`) and ensuring that re-running a single file atomically updates its specific entries in the CSV and ExtXYZ collections without affecting other files in the same folder.
- Decision: Unified both single-file and directory modes in `main()` so both write to/update the same central collections in the parent directory. Implemented two atomic, temp-file-safe transactional update helpers: `_update_csv_rows` and `_update_extxyz_collection`. When a structure is processed, any existing entries matching that filename/label are safely deleted and replaced with the new results in both the summary CSV and the ExtXYZ collection. Also, `BioMolFragmenter.extract` was extended with `write_files=False` so that individual window `.xyz` files are completely bypassed.
- Consequences: No individual `.xyz` files are written under any mode (MOF, COF, or Bio). Centralized collections (`fragments_collection.extxyz` and `fragmentation_summary.csv`) serve as the clean, single-point of output, while re-runs remain highly efficient and preserve existing directory progress.

## Decision 2026-05-22: Use label instead of name in ExtXYZ headers
- Context: The user requested replacing `"name"` with `"label"` in the header of the generated `fragments_collection.extxyz` file.
- Decision: Updated the Atoms `info` dictionary key from `"name"` to `"label"` across all three fragmentation modes (MOF, COF, Bio) in `fragmentation_oop.py`. This ensures that the ASE-written ExtXYZ comments consistently serialize as `label=...` rather than `name=...`.
- Consequences: Downstream ExtXYZ outputs automatically write the fragment identifier with a `label` key instead of a `name` key, matching the requested specification.

## Decision 2026-05-14: Unified batch folder processing architecture applies to all three modes (MOF, COF, Bio)
- Context: Batch folder processing, parallel `--nproc`, incremental CSV and ExtXYZ outputs were initially only implemented for the MOF mode. COF and bio modes were still single-file only.

## Decision 2026-05-13: MOF Linker Minimization utilizes topological skeleton pruning and bridge detection
- Context: The user noticed that for Mg-based MOFs (like MOF-74) and linkers with complex functional groups, the `--minimize` mode was inappropriately cutting atoms *inside* the aromatic rings. This was due to two flawed algorithms: an arbitrary BFS depth limit (`depth < 5`) in the native UniFrag path, and a hardcoded 6-membered Carbon-only ring finder in the Path J `moffragmentor` fallback which completely obliterated heterocycles like thiophene. Furthermore, redundant linkers in long organic chains were incorrectly saving all connected cycles.
- Decision: Completely rewrote the `minimize` trimming algorithms across all paths. They now use a mathematically perfect Topological Skeleton (2-core) Pruning algorithm. It starts with the entire linker molecule and iteratively deletes ANY atom (regardless of element) that has a connectivity degree of 1, UNLESS that atom is explicitly coordinating to a metal (`bridge_atoms`). For redundant/dangling linkers, it now explicitly maps "bridges" within the 2-core and truncates the structure immediately after the first biconnected ring system is isolated.
- Consequences: This guarantees mathematically perfect topological skeletons. The script effortlessly strips away all dangling functional groups (e.g. uncoordinated carboxylates, -OH, -NH2, -CH3) from the rings, perfectly preserves the entire cyclic ring structure (even non-carbon heterocycles like thiophene), and strictly truncates dangling linkers to just their very first ring system.
- Update: Enforced a new rule that `--minimize` is now handled automatically. The Python script will **automatically abort** and only return the normal un-minimized fragment if the total atom count of the normal fragment is predicted to be strictly less than 50 atoms. If the size is >= 50, it automatically generates both the normal and `_min` versions.
- Architecture Change: Shifted from relying on `run_mof_family.sh` for batch processing to a Python-native multiprocessing approach. `fragmentation_oop.py` now accepts a folder path as input, dynamically processes all enclosed CIF files using a configurable thread pool (`--nproc`), and automatically exports the `fragmentation_summary.csv` file natively. To ensure robustness and memory efficiency, both the CSV and the `fragments_collection.extxyz` collection are updated incrementally. Fragment names in the ExtXYZ header are automatically cleaned by replacing `[`/`]` with `_` and stripping the `.xyz` extension.

## Decision 2026-05-12: All extracted fragments must be a single connected component
- Context: The user noticed that some exported fragments occasionally contained disjoint sub-fragments (e.g., floating solvent molecules captured in the radius, or disconnected pieces remaining after extraction logic).

## Decision 2026-05-12: Aromatic H-caps are enforced globally planar via SVD fit for both Carbon and Nitrogen
- Context: The user noticed that capped hydrogens on aromatic rings (like phenyl linkers) were sometimes visibly out-of-plane. While the previous geometry enforcement calculated the local plane using the parent Carbon and its two immediate neighbors, thermal distortions in the CIF could misalign this local plane relative to the overall aromatic ring. Additionally, the collision guard prevented enforcement if UFF pulled the H into a tight spot, and the code explicitly ignored Nitrogen atoms (leaving imidazole rings broken).
- Decision: Upgraded `enforce_sp2_capped_h_geometry` to perform a Graph-BFS (up to 3 bonds) to find all heavy atoms in the aromatic ring. It computes the best-fit 3D plane using SVD (Singular Value Decomposition) on these atoms, and perfectly projects the local bisector vector onto this global average plane. Crucially, the target parent atom check was expanded to include Nitrogen (`"C"` and `"N"`), and the unreliable H-H collision guard was entirely removed.
- Consequences: All capped sp2 hydrogens (on phenyl, imidazole, pyridine, etc.) are now strictly and aggressively forced to mathematically align with the average 3D plane of their parent aromatic ring, guaranteeing rigorous planarity for QM calculations.

## Decision 2026-05-12: Bio-macromolecule fragments are strictly neutralized, minimally capped, and chemically deduplicated
- Context: The user requested fragmentation of single-chain biological macromolecules (PDBs). Furthermore, fragments must have exactly zero formal charge for QM calculations, and must not add heavy atoms (like ACE/NME) or invoke full-molecule optimization. The user also requested skipping duplicated fragments.
- Decision: Implemented `BioMolFragmenter` with a sequence-based sliding window (`--window-size`, `--stride`). Cut peptide bonds are capped strictly with a single H atom. Chemically identical windows (e.g. from highly repetitive motifs) are skipped to prevent redundant `.xyz` files, though they are still documented in the CSV.
- Consequences: Bio fragments are chemically valid for QM without fabricating phantom H atoms on interior atoms. PDB parser reads sequence linearly, independent of radius or graph searches.

## [2026-05-28] Partial Linker Minimization Logic
- **Decision:** When minimizing the SBU fragment, partial linkers must be cut after their first local cyclic unit (ring size <= 8), rather than preserving the entire structural 2-core.
- **Rationale:** A MOF linker can be a large fused ring system or contain macrocycles. If the entire 2-core is preserved, the `min` version becomes practically identical to the full structure, defeating its purpose. By explicitly finding the first local ring connected to the node, the min version correctly minimizes size while keeping the immediate coordination chemistry and rigidity.

## Decision 2026-09-17: Planar sp2 Capping Hydrogens on Terminal Nitrogen (COF only)
- Context: COF node/linker partitioning cleaves imine linkages (`Ar-N=CH-`), leaving a nitrogen with a single heavy neighbour. `COFFragmenter._cap_severed_double_bond_sites` saturates it to `Ar-NH2` and then relaxes the new H with UFF via `refine_h_geometry_with_rdkit`. UFF reproduces an *isolated* aniline, which is pyramidal, so the capping H end up ~0.76 A (max 0.93 A) out of the layer plane. In a stacked 2D COF dimer (layer spacing ~3.4 A) two such caps face each other and collapse to 1.72 A H...H. Measured on a 20-structure HCNO subset: **25 of 30 dimer frames** carried a sub-2.4 A interlayer contact, and **100% of those contacts were H-on-N** (50/50). The artefact sits in exactly the interlayer region the stacked dimer exists to represent, so it would contaminate the interlayer interaction in any QM label derived from these fragments.
- Decision: Added `COFFragmenter._planarize_conjugated_amine_caps`, invoked at the end of `_cap_severed_double_bond_sites`. For each terminal nitrogen that received capping H, it fits an SVD plane to the conjugated system reached through its single heavy neighbour (BFS over heavy atoms, depth <= 3, nitrogen included in the fit), then re-places the H in that plane at the two sp2 slots (+/-120 deg from the N-anchor bond). Existing N-H bond length is preserved. Guards: the plane fit needs >= 5 heavy atoms and max out-of-plane deviation <= 0.35 A, otherwise the UFF geometry is kept; only 1 or 2 capping H are handled.
- Rationale: In the parent COF the imine nitrogen is sp2 and rigorously coplanar with the ring, its lone pair conjugated into the sheet. Planar `-NH2` is therefore *more* faithful to the parent than UFF's pyramidal default, not a geometric hack. Aryl amines are near-planar for the same reason.
- Rejected alternative: capping the nitrogen with a single H. Measurement showed the existing `N-H1` sites are displaced 0.85 A out of plane - as far as the `NH2` ones - so halving the hydrogen count does not fix the clash, and `Ar-NH.` is an odd-electron radical that breaks the closed-shell assumption behind the QM labels.
- Scope: Nitrogen only. A terminal carbon cap is a genuine methyl (`-CH3`, sp3 tetrahedral); flattening it would be chemically wrong, and no methyl cap was ever found in an interlayer clash. The method lives on `COFFragmenter`, so MOF and biomacromolecule paths are untouched.

## Decision 2026-09-17: Layered-Dimer Rule Extended to COF Fallback Paths, Gated on Fragment Planarity
- Context: The stacked-dimer rule that gives a layered 2D COF fragment its interlayer environment lived only on Path J (`if 2.5 <= stack_len <= 5.0`). Structures that fell through to the Path A/B/C/D branch never reached it: the only dimer code there (`single_block_keep_heavy`) required `layer_mode == "dimer"` explicitly and so never fired under the default `"auto"`, and it was restricted to `path_mode == "A"`. On a 20-structure HCNO subset, 10 parents have a shortest lattice axis in the 2.5-5.0 A stacking window; 8 dimerized via Path J, while `411.cif` (Path A, c = 3.70 A) and `760.cif` (Path D, c = 3.56 A) silently produced monomers.
- Decision (two parts):
  1. Apply the same global layered-COF rule at the end of `COFFragmenter.extract`'s Path A/B/C/D branch, *after* capping and `fix_odd_electron_multiplicity` - matching Path J's ordering, so the second layer is an exact translation of one fully QM-ready monomer (identical capping in both layers, even electron count preserved by construction). A local `dimer_already_built` flag suppresses it when Path B already kept a second layer as a component, or when the `single_block_keep_heavy` block already duplicated.
  2. Gate the duplication on fragment planarity: the fragment's heavy atoms must fit a plane to within 0.5 A, and that plane's normal must align with the stacking axis to within `|cos| >= 0.8`.
- Rationale for the planarity gate: a short lattice axis alone does not prove a stacked 2D COF. `760.cif` has c = 3.56 A but its parent is corrugated - carbon spans 3.32 A and nitrogen 2.28 A of that 3.56 A repeat - so the fragment already fills the whole repeat. Translating it by c drops atoms onto neighbouring-cell positions and manufactures 1.5-2.0 A contacts. By contrast `411.cif` is rigorously flat in the parent: all 58 sites, including every one of its 21 hydrogens, sit at an identical z (spread 0.00 A). The gate separates the two cases exactly, and logs a reason when it declines.
- Consequences: `411` now dimerizes at |T| = 3.70 A; `760` correctly stays a monomer with the reason printed. Regression over the same 20 structures: only `411`'s three fragments changed; every other label kept its composition and component count. Scoped to `COFFragmenter.extract`, so MOF and biomacromolecule paths are untouched.

## Decision 2026-09-17: Symmetric (k+k) COF Node/Linker Tie-Break, Per-Site Linker Placement, Bond-Order-Aware Capping
Three linked defects surfaced by `411.cif` (a triformylphenol + tris(aminophenyl)benzene imine COF). All three are COF-only.

### 1. Node vs linker in symmetric COFs (`coffragmentor.py`)
- Context: `_count_linkages(...) >= 3` classifies a block as a node. In a k+k COF *both* building blocks carry the same number of linkages, so both were classified as nodes and `linkers` came back empty. For `411`, `COF.fragment()` returned the two correct blocks - `H6 C9 N3 O1` (phenol core) and `H15 C24 N3` (triaryl strut) - but both as nodes. `_try_coffragmentor_node_linker_fragment` requires both lists to be non-empty, so Path J bailed and the structure fell through to Path A, whose ad-hoc block growth produced a malformed node (two redundant carbons past the imine N) and a truncated linker.
- Decision: when the linkage rule yields **no** linkers **and** more than one distinct block type exists, break the tie by size - the smallest distinct type stays a node, every larger type is demoted to a linker. Blocks are grouped by `(weisfeiler_lehman_graph_hash, atom count)`.
- Rationale: the node is the compact rigid core, the linker the extended strut. Guarding on "no linkers at all" plus ">1 distinct type" leaves genuine single-block frameworks (self-condensed boroxine) and the ordinary asymmetric case untouched.

### 2. Linker images selected per attachment site, not per linker index (`fragmentation_oop.py`)
- Context: linker placement deduplicated candidate images by linker index, so at most one image per distinct linker SBU was attached. A symmetric COF has one symmetry-unique linker that must be placed at *every* node arm, so `411` came out as node + one linker instead of node + three. The minimized variant keeps the first linker whole and trims the rest, so with a single linker present it had nothing to trim, reduced the fragment by 0 atoms, and was dropped by the `MIN_ATOM_REDUCTION_FOR_MINIMIZE_COF` rule.
- Decision: score each candidate image with the set of node attachment atoms it reaches, then greedily accept images that cover at least one not-yet-covered attachment site, deduplicating on `(linker index, rounded image shift)`.

### 3. Capping hydrogen count must respect bond order (`fragmentation_oop.py`)
- Context: both capping sites computed `deficit = target_valence - neighbour_count`, treating every bond as single. A severed imine leaves `Ar-CH=N` with the C=N intact, so the nitrogen took two H and became an **iminium cation** (four bonds on N) instead of the neutral aldimine `Ar-CH=NH`. Across the 20-structure HCNO subset this produced **74 formally over-valent terminal sites** (64 `NH2-C=`, 6 `NH3-C=`, 4 `CH3-C=`), about 21% of all capped terminal sites.
- Decision: added `COFFragmenter._terminal_bond_order` (bond order from bond length) and `COFFragmenter._local_valence_used` (valence consumed, summing bond orders), and used them in both `_cap_severed_double_bond_sites` and the earlier Path A/B/C/D capping loop. Thresholds: double C=N <= 1.36, C=O <= 1.30, C=C <= 1.35, N=N / N=O <= 1.30; triple C#N <= 1.20, C#C <= 1.24.
- Rationale: bond length separates the cases cleanly - C=N 1.28 and ring C=N 1.34-1.35 versus aniline C-N 1.38-1.40 and amine C-N 1.47; nitrile C#N 1.16. Aromatic bonds (C-C 1.39, C-N 1.38) fall above every double-bond cutoff and so still score 1, leaving ordinary aromatic capping behaviour unchanged.
- Consequences: over-valent terminal sites 74 -> 4, and the 4 that remain are all in `760.cif`, whose parent CIF is geometrically distorted (C-N 1.154-1.338 A, every C-H exactly 1.140 A) rather than mis-capped. The 5 remaining under-valent sites are the deliberate `fix_odd_electron_multiplicity` removals, mirrored into both dimer layers.

## Decision 2026-09-17: Vinylene (sp2-Carbon) COF Linkage Chemistry
- Context: `704.cif` produced garbage through "Path A (Fallback single-center mode)". `COF.fragment()` returned 0 nodes and 3 "linkers" of 86 atoms each, with **zero severed bonds** - the three blocks were simply the structure graph's connected components, each still a periodic network rather than a molecular building block. None of the recognised linkage chemistries (boroxine B-O, imine C=N, oxazole/benzoxazole, 1,4-dioxin) is present in `704`: it is a vinylene-linked sp2-carbon COF, built by Knoevenagel/aldol condensation, whose linkage is a plain `Ar-CH=CH-Ar` carbon-carbon double bond.
- Decision: added a vinylene cleavage rule in `coffragmentor.py`. A C-C edge is severed when both carbons have exactly two heavy neighbours and exactly one H, the bond is at most 1.42 A, and it lies outside any small ring. The last condition is essential: an ordinary aromatic CH=CH edge is locally indistinguishable from a vinylene one and is protected only by its six-membered ring.
- Carry-over: carbon is normally excluded from `_CARRYOVER_ELEMENTS`, but the partner carbon of a severed vinylene bond is carried over (tracked in `vinylene_partner`). Each block therefore keeps an intact, planar `Ar-CH=CH2` vinyl terminus instead of collapsing to a tetrahedral `Ar-CH3`, mirroring how the imine rule leaves the aldehyde-derived block with its partner N.
- Consequences: `704` now resolves through Path J into a `H5 C11 N1` node and a `H27 C45 N3` linker, with all four fragment types and a working Min. `851` turned out to be a *mixed* imine/vinylene COF - it has three genuine C=C linkages at 1.331-1.333 A, present only in its 34- and 68-membered pore rings - so its blocks are now decomposed further, which is correct.

## Decision 2026-09-17: Planarize sp2 Capping Hydrogens, Carbon Included
- Context: the earlier planarization (2026-09-17, conjugated amine caps) was deliberately restricted to nitrogen, because a terminal carbon cap was assumed to be a genuine tetrahedral `-CH3`. The vinylene rule invalidates that assumption: a severed vinylene leaves a vinylidene `=CH2` terminus, which is sp2 and coplanar with its aryl ring. Leaving those to UFF reintroduced interlayer clashes in the layered COF `851` (3 fragments below 2.4 A, worst 1.72 A).

Nitrogen is planarized unconditionally, as before (both aryl amine and aldimine are planar).
- Consequences: sub-2.4 A interlayer contacts across the 20-structure regression went 3 -> 0, minimum contact 1.72 -> 2.55 A, with no other fragment changed. The bond-order test is what finally made this distinction expressible; it was not available when the nitrogen-only restriction was chosen.

## Decision 2026-09-17: Biaryl Fallback Deconstruction for All-Hydrocarbon COFs
- Context: `463.cif` (C48H30) produced only a malformed `H8 C14` node block and no linker, through "Path A (Fallback single-center mode)". `COF.fragment()` returned **0 nodes and 0 linkers**: the framework is built purely from aromatic rings joined by direct aryl-aryl C-C single bonds, so none of the recognised linkage chemistries (boroxine, imine, oxazole, dioxin, vinylene) matched and nothing at all was severed. Same silent-fallback outcome as `704`, but a third distinct cause.
- Decision: added a biaryl deconstruction rule in `coffragmentor.py`, running **only when no other linkage was found**. Most COFs contain biaryl bonds inside their linkers that must never be cut, so gating on "nothing else matched" is what makes the rule safe.
- Which biaryl bonds to sever is decided by **topology, not bond length**. Small rings (<= 7) are fused into ring systems; biaryl bonds connect different ring systems and lie outside any ring. A ring system reached by >= 3 biaryl bonds is a net vertex (a node); 2-connected systems are pieces of a strut. Only bonds touching a node are severed, which keeps a two-ring strut intact as one biphenyl linker rather than splitting it into two bare rings. If no ring system reaches degree 3 there is no vertex to anchor the deconstruction and nothing is cut.
- On `463` this severs exactly the six node-linker bonds (1.58 A) and keeps the three intra-biphenyl bonds (1.54 A) - reproducing the expected benzene node and biphenyl linker from connectivity alone, without relying on that 1.54/1.58 split. No carry-over applies (carbon is excluded except for vinylene partners), so the blocks stay plain rings as expected.
- Consequences on the 100-structure sample: fragment frames 259 -> 268, structures yielding fragments 90 -> 91, Min coverage 88 -> 89, sub-2.4 A dimer contacts 14 -> 11. `632` went from producing nothing to all four fragment types; `1049`, `1127`, `135`, `362`, `365` gained node/linker decomposition. Valence quality unchanged at ~96%.

## Decision 2026-09-17: Alkyne-Aware Carbon Capping, Measured Stackability, Topology-Aware COF Duplicate Key
Three defects found via `543.cif` and `612.cif`. All are COF-scoped; MOF behaviour is provably unchanged.

### 1. No capping H on a fully valent sp carbon (`_cap_open_oxygens`)
- `_cap_open_oxygens` adds one H to any carbon with exactly two heavy C/N neighbours and no hydrogen - the signature of an aromatic edge carbon that lost its H. An **alkyne** carbon in an `Ar-C#C-Ar` linkage matches that signature exactly but is already fully valent (triple bond 3 + aryl single 1 = 4), so `543.cif` came out with a spurious H on its C#C chain. The parent CIF has no H there at all.
- `_cap_open_oxygens` lives on `BaseFragmenter` and is shared with MOF, so the bond-order test could not be inlined. Added the no-op hook `BaseFragmenter._skip_aromatic_carbon_h_cap` (returns False, leaving MOF and macromolecule behaviour byte-identical) and overrode it in `COFFragmenter` to veto the cap when `_local_valence_used(idx) >= 4`. A real aromatic edge carbon's two ~1.39 A bonds score only 2, so it still gets its H. Verified: `MOFFragmenter._skip_aromatic_carbon_h_cap is BaseFragmenter._skip_aromatic_carbon_h_cap`.

### 2. Stackability judged relative to the repeat, then measured directly
- The layer-planarity guard used an absolute 0.5 A flatness cutoff. `543.cif` is unambiguously a stacked 2D COF (c = 3.58 A; its N and O atoms are perfectly coplanar) whose aryl rings twist 0.5-0.89 A out of the mean plane, so the guard rejected it and produced a monomer.
- Corrugation is now judged **relative** to the stacking distance (`flatness <= max(0.6, 0.30 * |T|)`), which separates `543` (0.5 A over a 3.58 A repeat) from `760` (2.5 A over 3.56 A). The geometric test is then backed by the criterion it was only ever a proxy for: the second layer is actually placed and the closest interlayer contact measured, and the dimer is rejected if that falls below 2.4 A. Skips are logged with the measured values.

### 3. COF duplicate key must include topology
- `_chemical_identity_key` keys on the heavy-atom formula alone. Distinct COFs routinely share a formula, so the colliding fragment was silently dropped as a duplicate. On the 100-structure HCNO sample this discarded the **normal fragment of 14 of 100 structures**; `612.cif` survived as a single linker with no normal, no min and no node, and for `141`/`144` *both* members were dropped so nothing of that formula remained.
- Added a `COFFragmenter._chemical_identity_key` override: heavy-atom formula plus an element-labelled Weisfeiler-Lehman hash of the heavy-atom bond graph. Raw geometry remains unusable as a key (lattice differences shift every distance, which is why the MOF key avoids it), but connectivity is invariant to that noise while still distinguishing different molecules.
- Scoped by dispatch, not by editing the shared code: `_flush_cof_result` and the `seen_keys` seeding now select the key function by `args.kind`, so `_flush_mof_result` keeps the MOF formula-only key untouched.
- Verified: `612` now emits all five frames; `141`/`144` and `579`/`603` still deduplicate because their topology hashes genuinely match - they are real duplicate entries in CoRE-COF.

## Decision 2026-09-17: Stacked Dimers From Crystal Symmetry, Not Only Translation (AB/Staggered COFs)
- Context: dimer construction only ever duplicated a fragment along a short lattice vector, which assumes AA (eclipsed) stacking. `585.cif` is space group **P6_3/m**: successive layers are related by the 6_3 **screw axis** - rotated 60 degrees and shifted by c/2 - and it packs two layers per cell, so its c parameter is 7.00 A. A translation-only rule sees no lattice axis in the 2.5-5.0 A window at all and silently produced a monomer, even though the layers are a textbook 3.50 A stack.
- Decision: replaced the fixed "translate along the shortest axis" rule with `COFFragmenter._find_stacked_partner`, which returns a general operation `(R, t, local)` and searches three candidate classes in order:
  1. **Pure lattice translations** along each axis - the AA case, tried first so every previously working structure keeps exactly its old behaviour.
  2. **Crystal symmetry operations**, covering screw axes and glides where the fragment sits on the symmetry element.
  3. **Local screw**: the crystal's own rotation angle applied about the axis through *this fragment's* centroid. Needed because `585`'s node does not lie on the 6_3 axis - that axis runs through a pore, so layer 2's node sits over layer 1's pore and the crystallographic image of the fragment lands ~19 A to the side. The interlayer *environment* is still "the same motif, rotated 60 degrees, 3.5 A above", so this reproduces the AB contact geometry faithfully without pretending to be a crystallographic overlay.
- Every candidate must pass the same checks: interlayer separation 2.5-5.0 A, lateral offset <= 2.0 A (the copy must sit ON the fragment, not beside it), and a measured closest contact >= 2.4 A. Ties are broken by nearest layer, then **smallest rotation** - the primitive screw is the true adjacent-layer relationship, and without that tie-break different fragments of one structure picked different equivalent operations (`585`'s FragCof chose 180 degrees while its Min chose 60).
- `partner_vec` (a translation) is generalised to `partner_op = (R, t, local)`, applied through `_apply_partner_op`. A `local` operation rotates about **each block's own centroid**, which is essential because the node and linker library blocks have different centroids from the assembled fragment; applying the fragment-centred transform to them put the two halves 33-38 A apart.
- Two traps worth recording: `lattice_reduce` must slide a displacement **laterally only**, keeping it one layer away. Minimising total length instead collapses a pure lattice translation straight back to zero, which silently removed *every* dimer in the 20-structure regression.
- Consequences: `585` now yields all four fragments as dimers, consistently 60-degree rotated, 3.50 A separation, 0.00 A lateral offset, 3.50 A closest contact. On the 20-structure regression all 24 placements still resolve to a plain lattice translation, compositions are unchanged, and dimers went 33 -> 34 with zero sub-2.4 A contacts.

## Decision 2026-09-17: Linkage-Recognition Diagnostic
- Context: the cleavage rules are enumerated by hand (boroxine, imine, oxazole, dioxin, vinylene, biaryl). A COF whose linkage is absent from that list has **nothing** severed; `COF.fragment()` then returns the structure's connected components - often still-periodic networks - which look like building blocks but are not, and the caller quietly drops to its crudest fallback path. The run exits 0 and writes plausible files. `704.cif` (vinylene) and `463.cif` (biaryl) both reached the user this way and were caught only by eye.
- Decision: `FragmentationResult` now carries `n_cut_bonds` and `linkage_types`, and `COFFragmenter._report_linkage_recognition` prints, once per structure, either the recognised linkage types and bond count or a greppable warning:
  `!! UniFrag COF WARNING [stem]: no known linkage chemistry recognised (0 bonds severed).`
- The boroxine, imine and vinylene rules previously severed bonds without tagging them, so the report mislabelled `704` (vinylene) as "boroxine/imine". They now tag their bonds. Tags are keyed **per bond** (`frozenset` of the atom pair), never per linkage type: `_count_linkages` merges bonds that share a tag, so a per-type tag would collapse every imine in a block into a single linkage and wreck node/linker classification. Verified inert - the 20-structure regression is byte-identical in frames, compositions and dimers.

## Decision 2026-09-17: Imine Cleavage Stays Length-Blind (proposed bond-length guard REJECTED)
- Proposal: `612.cif` exports a 4-atom `C2 N2` block as a linker. The imine rule cuts any C-N bond on a 2-connected carbon without checking the bond length, and the bonds flanking `612`'s acetylene bridge are 1.438 A - ordinary single bonds, not imines (a real imine C=N is ~1.28 A). Requiring `<= 1.36 A` looked like the obvious fix.
- Measurement over 100 structures - 810 C-N bonds that the rule currently cuts:
  `p25 = 1.292, p50 = 1.301, p75 = 1.348, p95 = 1.447, p99 = 1.510`
  | threshold | bonds dropped | structures losing ALL cuts |
  |---|---|---|
  | 1.34 | 228/810 | 23 |
  | 1.36 | 160/810 | **15** |
  | 1.38 | 123/810 | 11 |
  | 1.45 |  40/810 | 4 |
- **Decision: rejected.** A quarter of the bonds this rule cuts are genuinely long C-N (1.40-1.51). For many COFs the linkage really is a C-N single bond - amine- and triazine-linked frameworks - and the cuts are load-bearing. At the proposed 1.36 A cutoff, 15 of 100 structures would lose *every* cut and fall to the fallback path, including `543` and `585`, both fixed earlier today. The rule's length-blindness is doing real work, not being sloppy.

The block is therefore the acetylene strut plus its two carried-over attachment nitrogens, exported as `H2N-C#C-NH2` - exactly what the agreed carry-over convention produces for any linkage, and a faithful representation of that connection point. Not a defect; left as is.

## Decision 2026-09-17: Imine Rule Must Not Cut a TERMINAL Nitrogen (760)
- Context: `760.cif` produced wrong normal/min fragments and no node or linker libraries. `COF.fragment()` reported 8 bonds severed yet returned a single 236-atom "node" - the entire unit cell - and zero linkers, so Path J bailed and the structure fell to the Path D porphyrin fallback.
- Root cause: the 8 severed bonds were `760`'s **nitrile** `Ar-C#N` groups. The imine rule cuts any C-N bond whose carbon has two heavy neighbours, and a nitrile carbon qualifies (aryl carbon plus N). Cutting them decomposes nothing - it just lops 8 terminal nitrogens off the framework - but it was enough to make `edges_to_remove` non-empty, which suppressed the biaryl fallback (gated on "nothing else matched"). The structure's real linkage is biaryl.
- Decision: the imine rule now also requires the **nitrogen** to have at least two heavy neighbours. A linkage nitrogen always bridges two units; a terminal nitrogen is a substituent - a nitrile or a free amine - and severing it removes a functional group rather than a linkage.
- Consequences: `760` now resolves through Path J via the biaryl rule into a `H6 C16` fused-core node and a `H16 C28 N4` linker, matching the user's reference images, and emits all four fragment types plus both libraries. It also **keeps its nitrile nitrogens**, which were previously being cut away: `760FragCof` went from `C102H72N4` to `C128H82N16`. The 20-structure regression changed nothing else - 760 was the only structure affected, gaining `OnlyNode` and `OnlyLinker`.

## Open Issue 2026-09-17: Under-Capped Nitrogen in 167 - parity is forced, no benign fix
- Symptom: two nitrogens per `167` fragment carry a C=N (1.35 A) and **no** hydrogen - an iminyl/nitrene site.
- Mechanism: capping correctly produces the aldimine `Ar-CH=NH`; `fix_odd_electron_multiplicity` then strips that single H to force an even electron count, leaving nitrogen with one connection.
- Why it cannot simply be redirected: for a neutral closed-shell CcHhNnOo the electron count is even iff `h + n` is even. `167`'s monomer is `C42H30N9O3`, so `h + n = 39` - odd - and exactly one hydrogen must be added or removed. Instrumenting the fragment at that moment shows **every** removal candidate is an aldimine N (three of them, nH=1, bond 1.35 A); there is no aniline `-NH2` to strip instead. Nor is there a valid site to ADD to: every nitrogen is already valence-complete (aldimine 2+1, junction 2+1, aniline 1+2), and the 30 carbons that look deficient are aromatic - an artefact of `_local_valence_used` scoring aromatic bonds as single.
- So the composition genuinely admits no closed-shell neutral capping, and the current behaviour picks the most damaging site available. Options, none yet chosen:
  1. Rank removal sites by resulting damage - prefer a true primary amine (`-NH2` -> `-NH`, nitrogen keeps two connections) over an aldimine (`-CH=NH` -> `-CH=N`, one connection). Helps other structures; does nothing for `167`, which offers only aldimines.
  2. Stop mutilating the cap and instead record the fragment as open-shell (`multiplicity=2`) in the extxyz, letting the QM step treat it honestly. Best chemistry; needs downstream support.
  3. Adjust the fragment boundary so `h + n` comes out even by construction. Most correct, most invasive.

## Decision 2026-09-18: Electron-Parity Repair Runs on the FINAL System, After Dimerisation
- Context: `167.cif` emitted a nitrogen carrying a C=N and no hydrogen - RDKit cannot even assign it a valence ("Unable to determine valence of atom 58 with atomic number 7 and 1 bonds"). The cap itself was correct: `_cap_severed_double_bond_sites` produced the aldimine `Ar-CH=NH`, and `fix_odd_electron_multiplicity` then stripped its only H to force an even electron count, leaving a nitrene.
- The fix is not a better choice of which hydrogen to sacrifice - it is not sacrificing one at all. **Parity was being checked on the monomer, before the second layer was added.** `167`'s monomer has Z_sum = 369 (odd), but the emitted dimer is 2 x 369 = 738, which is already even. The repair was mutilating a cap to solve a problem the emitted fragment did not have.
- Decision: `fix_odd_electron_multiplicity` is now called **after** the stacked-dimer block in both `_try_coffragmentor_node_linker_fragment` (Path J) and the Path A/B/C/D branch of `extract`, so it always sees the final system. `capped_h_indices` is extended across the duplicated layer so the repair can still see both copies. The node/linker library exports were already correct - they duplicate first and call `_make_cof_qm_ready` on the doubled block.
- Also changed, per the user's requirement of multiplicity = 1: when parity genuinely must be repaired, **adding** a hydrogen is now preferred over removing one, since adding leaves every existing atom valence-complete while removing necessarily creates an under-coordinated site. Gated by `BaseFragmenter._prefer_h_addition_for_parity` (False) and overridden True in `COFFragmenter`, so MOF and macromolecule behaviour is byte-identical. Add-eligibility is filtered by `_can_accept_extra_h`, a hook that is permissive on the base class and bond-order aware in `COFFragmenter` - a reconnected imine junction (Ar-CH=N-Ar) has two heavy neighbours and no H and so looks eligible, but its C=N already uses two of nitrogen's three valences and adding an H would make an iminium cation.
- Validation on the 20-structure set: parity-repair events **7 -> 1**; fragments that RDKit accepts as neutral, closed-shell, zero-radical **75 -> 77 of 78**; zero odd-electron fragments; Min coverage 20/20, 34 dimers, minimum interlayer contact 2.55 A, zero sub-2.4 A contacts, no fragment gained or lost. The only three composition changes are fragments **gaining** hydrogen as their caps are restored (`167FragCof`, `167FragCofMin`, `851FragCof`).
- Remaining: `142FragCofMin` is a genuine monomer with an odd composition and no benign repair site, so one cap is still sacrificed there. 1 of 78.

## Decision 2026-09-18: Saturation Guard Generalised From Carbon to N and O
- Context: the first full 100-structure re-run after today's fixes showed over-valent terminal sites rising 46 -> 89. Breaking them down, almost all were `N + 1H on a C#N` at 1.11-1.20 A - a hydrogen sitting on a **nitrile nitrogen**.
- Cause: the terminal-nitrogen guard added for `760` correctly stopped the imine rule from severing nitriles, so nitriles are now **retained** in fragments. But `_cap_open_oxygens` then protonated them: its nitrogen branch fires on any N with exactly one heavy neighbour and no hydrogen, which is precisely a nitrile's signature. The bond-order guard added earlier covered only its carbon branch, so more retained nitriles meant more spurious N-H.
- Decision: the hook `_skip_aromatic_carbon_h_cap` is generalised to `_skip_saturated_h_cap` and applied to **every** branch of `_cap_open_oxygens`, before the per-element rules. Base implementation still returns False, so MOF and macromolecule behaviour stays byte-identical; the `COFFragmenter` override vetoes any atom whose bond-order valence already meets its target. This covers the nitrile nitrogen (C#N = 3), the alkyne carbon (3 + 1 = 4) and a carbonyl oxygen (C=O = 2), while leaving the genuine cases untouched - an aromatic edge carbon's two ~1.39 A bonds score only 2, and a severed amine nitrogen's single ~1.40 A bond scores 1.
- Validation on the 20-structure set: over-valent terminal sites **12 -> 0**, correctly capped 367 -> 381, with frames, Min coverage, dimer count, minimum interlayer contact and odd-electron count all unchanged. The 10 composition changes are all fragments shedding spurious hydrogen - `760FragCof` loses exactly 8, one per nitrile.
